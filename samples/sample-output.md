# Implementation Plan

_Source: `sample-prd.pdf` · 2 pages · 17 tasks · 14 requirements · generated by `cli`/`claude-sonnet-5` · plan id `44d249ee66ea861a`_

## Summary

SplitTab is a mobile-first web app for small groups to log shared expenses, see always-accurate per-member balances, and get the minimum set of payments that settles the group. The hardest part is the money model: every amount and split must be integer minor units that reconcile exactly to the cent across equal/exact/percentage splits, edits, and a settlement algorithm whose correctness is proven with property-based tests.

## Requirements

| ID | Category | Requirement |
|---|---|---|
| FR-1 | auth | A user signs up with email and password, and signs in to receive a session. Passwords are stored hashed. Sessions expire after 30 days. |
| FR-2 | groups | A signed-in user can create a group with a name and a base currency. The creator becomes the owner and the first member. There is exactly one owner and ownership can be transferred; the owner can rename the group and remove members. |
| FR-3 | invitations | An owner can invite a member by email. The invitation produces a single-use link valid for 7 days. Accepting it adds the user to the group. |
| FR-4 | expenses | A member records an expense with description, amount, date, payer, and shared members, split equally, by exact amounts, or by percentage shares. Splits must sum to the total; a mismatch is rejected with the difference. |
| FR-5 | expenses | Any member can edit or delete an expense. Every change is recorded in an immutable audit trail showing who changed what and when. Balances recompute after any edit. |
| FR-6 | balances | Each member sees, for every group, what they owe and what they are owed, per counterparty. The sum of all balances in a group is always zero. |
| FR-7 | settlement | A member can ask for a settlement plan: the minimum number of payments that brings every balance to zero. Recording a settlement payment updates balances the same way an expense does. |
| FR-8 | notifications | A member receives an email when added to a group, when an expense involving them is recorded, and a weekly digest of open balances. Each is individually switchable. |
| FR-9 | export | A member can export a group's expense history as CSV, covering an optional date range, with one row per expense and one column per member's share. |
| FR-10 | activity | A group has a reverse-chronological activity feed of expenses, edits, settlements, and membership changes, paged at 50 entries. |
| NFR-1 | money | Money is never stored or computed in floating point. All amounts are integer minor units, and every split must reconcile to the cent. |
| NFR-2 | performance | A group of 20 members with 5,000 expenses loads its balance view in under 500 ms at the 95th percentile. |
| NFR-3 | security | Every write is authorised against group membership. A user must not be able to read or alter a group they do not belong to, including by guessing an id. |
| NFR-4 | testing | The settlement algorithm is covered by property-based tests asserting that resulting balances are all zero and no member pays more than they owed. |
