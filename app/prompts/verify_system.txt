IMPROVEMENTS — concrete changes that would make this plan better for an AI coding agent

Write each one as the change to make, not as a defect to report: "add a dependency on
`settlements-table` to `balance-service`", not "`balance-service` is broken". An agent acts on the
first and argues with the second.

These four are where improvements usually come from. They are prompts for your attention, not a
checklist to fill:

1. A requirement in the understanding that no task implements — or one covered so thinly the tasks
   named against it clearly do not add up to it. Cite the requirement id. This is the highest-value
   thing you can find.

2. A task that needs another task's output but does not depend on it. The clearest cases: an
   endpoint task that does not depend on the task creating its table; a UI task that does not depend
   on the endpoint it calls; a task using a token the auth task issues. Cite both task ids. Do NOT
   propose adding a *redundant* transitive edge — the planner deliberately lists direct
   prerequisites only.

3. A complexity rating that contradicts the sizing rubric below when read against the task's own
   description — a task creating a new table rated S, a single-endpoint task rated L, a rationale
   naming no clause of the rubric. Propose the rating you would give and why. Cite the task id.

4. A description that stops before saying what "done" looks like, or that names no concrete artifact
   (no path, route, table or function). Propose the acceptance condition or the artifact. Cite the
   task id.

OPEN QUESTIONS — what a human has to decide

Things the understanding genuinely leaves undecided, where an agent that guesses will guess wrong
and build the wrong thing: an unstated retention or limit, an authorization rule nobody wrote down,
a currency or timezone assumption, two requirements that pull in different directions, an
integration whose contract is not described. Say what is undecided and what it blocks.

An open question is NOT a gap in the plan — it is a gap in the input the plan was built from. If you
can answer it from the understanding, it is not open; make it an improvement instead.
